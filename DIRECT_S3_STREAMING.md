# Direct S3 Streaming - Zero Server Bandwidth

## 🎯 Overview

Devices now stream videos **DIRECTLY from S3** using secure pre-signed URLs, eliminating server bandwidth usage and improving performance.

### Before vs After

**Before (Through Server):**
```
Device → Server → S3 → Server → Device
         ↓ 
    Server bandwidth: 100%
    Server CPU: High (streaming)
    Bottleneck: Server capacity
```

**After (Direct S3):**
```
Device → Server (get URL only) 
Device → S3 (stream directly)
         ↓
    Server bandwidth: ~0.01% (just URL)
    Server CPU: Minimal
    Bottleneck: None (S3 scales infinitely)
```

## 📝 Features Implemented

### 1. New API Endpoint

**GET `/api/videos/:videoId/stream-url`**

- Returns secure pre-signed S3 URL
- Valid for **30 minutes** (1800 seconds)
- No authentication required (URL itself is the security)
- Perfect for device players and direct streaming

### 2. New S3 Utility Function

**`getDownloadSignedUrl(s3Key, expiresIn)`**

- Generates pre-signed URLs for S3 downloads
- Configurable expiry time (default 30 minutes)
- Uses AWS Signature Version 4
- Secure cryptographic signature

### 3. Updated Device Player

- Requests stream URL from server
- Streams directly from S3
- Caches directly from S3
- Tracks URL expiry time

## 🔒 Security

Pre-signed URLs are **highly secure**:

✅ **Generated by server** - Only server has AWS credentials  
✅ **Cryptographic signature** - Can't be forged or modified  
✅ **Time-limited** - Expires after 30 minutes  
✅ **File-specific** - Limited to exact S3 object  
✅ **No credential exposure** - AWS keys never sent to client  

### Pre-signed URL Structure

```
https://signagelogicalvalley.s3.ap-south-1.amazonaws.com/videos/dev_test_xxx_yyy.mp4
  ?X-Amz-Algorithm=AWS4-HMAC-SHA256
  &X-Amz-Credential=ACCESSKEY/20251228/ap-south-1/s3/aws4_request
  &X-Amz-Date=20251228T180000Z
  &X-Amz-Expires=1800
  &X-Amz-Signature=abc123def456...
  &X-Amz-SignedHeaders=host
```

**Security features:**
- `X-Amz-Signature`: Cryptographically signed by AWS
- `X-Amz-Expires`: Max 30 minutes from generation
- `X-Amz-Date`: Timestamp prevents replay attacks
- Cannot be modified without invalidating signature

## 🔄 How It Works

### Video Streaming Flow

```
┌─────────┐     (1) Request stream URL        ┌─────────┐
│ Device  │─────────────────────────────────▶│ Server  │
└─────────┘                                   └─────────┘
                                                    │
                                                    │ (2) Validate video
                                                    │ Check S3 file exists
                                                    │ Generate pre-signed URL
                                                    ↓
┌─────────┐     (3) Return pre-signed URL    ┌─────────┐
│ Device  │◀─────────────────────────────────│ Server  │
└─────────┘     (JSON with URL, expires, etc) └─────────┘
     │
     │ (4) Stream directly from S3
     │     (Server not involved!)
     ↓
┌─────────┐
│   S3    │◀───── Validate signature & expiry
└─────────┘       Stream video data
     │
     │ (5) Video data
     ↓
┌─────────┐
│ Device  │──────▶ Play video
└─────────┘
```

### Video Caching Flow

```
1. Device wants to cache video
2. GET /api/videos/:videoId/stream-url
3. Server returns pre-signed URL (30 min expiry)
4. Device downloads directly from S3
5. Device stores in IndexedDB cache
6. Available for offline playback
```

## 🔧 API Reference

### GET /api/videos/:videoId/stream-url

Get a pre-signed URL for direct S3 streaming.

#### Request

```http
GET /api/videos/abc-123-def-456/stream-url
```

#### Response (Success)

```json
{
  "success": true,
  "data": {
    "streamUrl": "https://signagelogicalvalley.s3.ap-south-1.amazonaws.com/videos/dev_test_xxx_yyy.mp4?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=...",
    "videoId": "abc-123-def-456",
    "fileName": "video.mp4",
    "fileSize": 15728640,
    "duration": 60,
    "expiresIn": 1800,
    "expiresAt": "2025-12-28T18:30:00.000Z"
  }
}
```

#### Response (Error)

```json
{
  "success": false,
  "message": "Video not found"
}
```

#### Fields

| Field | Type | Description |
|-------|------|-------------|
| `streamUrl` | string | Pre-signed S3 URL for direct streaming |
| `videoId` | UUID | Video identifier |
| `fileName` | string | Original file name |
| `fileSize` | number | File size in bytes |
| `duration` | number | Video duration in seconds |
| `expiresIn` | number | URL validity in seconds (1800 = 30 min) |
| `expiresAt` | ISO8601 | Absolute expiry timestamp |

## 🚀 Migration Guide

### For Device Players

**Old Code:**
```javascript
const videoURL = `/api/videos/${videoId}/download`;
videoElement.src = videoURL;
```

**New Code:**
```javascript
const response = await fetch(`/api/videos/${videoId}/stream-url`);
const { data } = await response.json();
videoElement.src = data.streamUrl;
```

### For Mobile Apps

**Old Code:**
```swift
let url = "https://yourserver.com/api/videos/\(videoId)/download"
player.url = URL(string: url)
```

**New Code:**
```swift
let response = await fetch("https://yourserver.com/api/videos/\(videoId)/stream-url")
let data = try JSONDecoder().decode(StreamResponse.self, from: response.data)
player.url = URL(string: data.streamUrl)
```

## ⚡ Best Practices

### 1. URL Caching

Don't cache pre-signed URLs longer than their expiry:
```javascript
// ✅ Good
const { data } = await getStreamURL(videoId);
if (Date.now() < new Date(data.expiresAt).getTime()) {
  // Use cached URL
} else {
  // Request new URL
}

// ❌ Bad
const url = localStorage.getItem('videoUrl'); // May be expired!
```

### 2. Error Handling

Handle URL expiry gracefully:
```javascript
videoElement.addEventListener('error', async (e) => {
  if (e.target.error.code === MediaError.MEDIA_ERR_SRC_NOT_SUPPORTED) {
    // Might be expired URL, get new one
    const { data } = await getStreamURL(videoId);
    videoElement.src = data.streamUrl;
  }
});
```

### 3. Prefetching

For playlists, prefetch URLs before they're needed:
```javascript
// Prefetch next 3 videos
for (let i = currentIndex + 1; i <= currentIndex + 3; i++) {
  if (playlist[i]) {
    getStreamURL(playlist[i].videoId); // Cache the URL
  }
}
```

## 🐛 Troubleshooting

### Problem: "Access Denied" errors

**Cause:** AWS credentials not configured or incorrect region

**Fix:**
```bash
# Check .env file
cat .env | grep AWS

# Should have:
AWS_REGION=ap-south-1
AWS_ACCESS_KEY=AKIAUBXTMC5EL3UZFPXA
AWS_SECRET=your_secret_key
AWS_S3_BUCKET=signagelogicalvalley
```

### Problem: URLs expire too quickly

**Cause:** Default 30-minute expiry might be too short for some use cases

**Fix:** Increase expiry in `utils/s3Storage.js`:
```javascript
// Change from 1800 (30 min) to 3600 (60 min)
const getDownloadSignedUrl = (s3Key, expiresIn = 3600) => {
  // ...
}
```

### Problem: CORS errors

**Cause:** S3 CORS not configured correctly

**Fix:** Update S3 CORS configuration:
```json
[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedOrigins": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```
